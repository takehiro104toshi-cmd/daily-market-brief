# FACT_ANALYSIS_FORECAST_SPEC — 事実・分析・予測の分離仕様

Phase 0（Compass DNA解析）成果物。対象: 2026/06/18〜07/01 の10冊。
将来の Source / Evidence Engine（Phase 1）の設計根拠となる、羅針盤の文章の
FACT / ANALYSIS / FORECAST 分離規約を抽出する。

---

## 1. 三分類の定義（羅針盤の実運用から帰納）

| 分類 | 定義 | 言語マーカー（観測） |
|---|---|---|
| FACT | 検証可能な出来事・数値。日付・数値・主体を伴う | 「〜した」「〜と発表した」「〜が決定された」「（6/17）」等の日付併記、表・チャートの実測値 |
| FACT(未確認) | 報道ベース・伝聞の事実。出所の弱さを文法で明示 | 「〜と伝わっている」「一部報道によれば」「〜もよう」「〜と報じられた」 |
| ANALYSIS | 事実間の因果・解釈。現在形の推論 | 「背景には〜があろう」「〜とみられる」「〜が意識された」「〜につながると考える」「〜を好感した」 |
| FORECAST | 将来の状態の予測 | 「〜を想定する」「〜となろう」「〜が期待できよう」「〜そうだ」「〜とみる」 |

**重要な発見**: 羅針盤は文単位でこの三態が判別できるよう書かれている。
1つの段落は典型的に「FACT（昨晩・日付付き）→ ANALYSIS（背景・因果）→ FORECAST（本日・今後）」の順で進む（CONFIRMED: 全号のP1リード段落）。

## 2. FACTの出典規約（CONFIRMED）

1. **表・チャートは必ず出典3点セット**: 「出所：X」＋「作成：岡三証券」＋データ基準日（例:「6月22日現在」）。算出条件（週次/日次、休場時の扱い、対象母集団）も脚注化。
2. **観測された出所の階層**（Tier構造が実在する）:
   - Tier 1（一次情報）: 会社資料、日本取引所グループ、経済産業省、政府発表、中銀（FOMC・日銀）、Statista
   - Tier 2（市場データ・高信頼報道）: QUICK、LSEG Workspace、各種報道（日付付き引用）
   - Tier 3（伝聞）: 「一部報道」「〜もよう」——本文の文法で弱さを明示し、断定しない
3. **要人発言は（発言者 日付）を必ず付す**（P2要人発言欄・全号）。
4. **数値は加工方法を明示**: 「25日MAの前日比は乖離率」「単純平均」「騰落率ベース」「中央値」「予想はQUICKコンセンサス（3社以上）」等。
5. **自社予想と会社計画と市場予想を区別**: 「会社計画」「市場予想」「岡三証券では〜と予想する」を書き分ける（6/29 P4 住友化学、6/26 P4 東エレク）。

## 3. FORECASTの確信度ラダー（観測された語彙の強度順）

| 強度 | 表現 | 用途 |
|---|---|---|
| 5（最強・行動示唆） | 「投資妙味」「追随したい」「押し目を拾うスタンスで臨みたい」「押し目買いの好機」 | 明確な推奨。中長期テーマ×調整局面で使用 |
| 4（基本シナリオ） | 「〜を想定する」「〜を見込む」「〜となろう」「〜しよう」 | 当日・目先のメインシナリオ |
| 3（期待） | 「〜が期待できよう」「〜期待したい」「〜に期待」 | 蓋然性はあるが確度を落とす |
| 2（監視） | 「注目したい」「注目される」「焦点となろう」「動向が注目されよう」 | 方向を断定しない観察対象 |
| 1（可能性） | 「可能性がある」「場面もありそうだ」「余地がありそうだ」「〜も想定しておきたい」 | テールシナリオ・リスク側 |
| 0（条件付き） | 「〜となれば〜だろう」「内容次第では」 | 条件分岐の明示 |

- 為替見通しのみ、**必ず数値レンジ**（「予想レンジは1ドル＝161〜162円」）を提示する（CONFIRMED: 為替回全4号）。
- 株式見通しは方向＋条件で示し、指数の数値目標は日常的には出さない（水準言及は「7万円台維持」「25日MA=67,000円程度」のような節目参照に限る）。LIKELY。

## 4. ANALYSISの作法（CONFIRMED）

1. **因果は比較で語る**: 単独の値動きでなく「AかつB→C」の形（例: 米株安＋先物横ばい→底堅い。金利上昇＋割安金融→追い風）。
2. **反対材料を併記**: 「もっとも」「他方」「一方」で逆風・留保を同一記事内に必ず置く。
3. **経験則はそれと明示**: 「〜という経験則を有する」（6/22 配当再投資）——統計的規則性と因果的推論を区別する。
4. **検証を伴う分析**: 主張の裏に定量検証を添える（SOX相関係数チャート 6/26、PER±1σバンド 6/23、時点比較 6/30）。

## 5. Evidence Engine への設計要件（Architecture Recommendation）

Phase 1 で実装すべき最小要件（羅針盤の規約の機械化）:

1. 文単位の `statement_type: fact | fact_unverified | analysis | forecast` タグ。
2. FACTには `source`（名称・URL）, `source_tier: 1|2|3`, `event_date`, `retrieved_at` を必須化。伝聞は `fact_unverified` とし、生成文で「〜と伝わる」系の語尾を強制する。
3. FORECASTには `confidence: 0-5`（§3のラダー準拠）と `horizon: intraday | 1d | 1w | medium | long` を必須化し、語尾テンプレートを confidence から機械的に選択する。
4. 数値には `unit`, `as_of`, `calc_method`（乖離率/変化幅/騰落率等）をメタデータとして保持する。
5. 「会社計画/市場予想/自社分析」の予想主体を `forecast_agent` として区別する。
6. 反対材料フィールド（`counter_points`）を各見通しオブジェクトに持たせ、空なら生成を許可しない（§4-2の機械化）。
