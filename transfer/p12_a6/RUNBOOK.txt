3. If a stage fails
-------------------
- The helper prints FAIL <code> and STAGE_FAIL <stage>, then (if tasks were installed) FAILSAFE_REMOVE ... which removes ONLY the
  A6-owned tasks (\Compass\P12\a6-validation\*). Nothing else is removed; no evidence is deleted. Paste the REPORT lines and STOP.
- FAIL P9_MUTATED / P10_MUTATED: a root changed since preflight. STOP and report; the helper never repairs anything.
- FAIL REFUSED_NEAR_MIDNIGHT_RETRY_LATER: start again after 00:20.
- FAIL P12_ROOT_NOT_EMPTY_USE_ARCHIVE_PREVIOUS or STATE_PRESENT_USE_RESUME_OR_ARCHIVE_PREVIOUS: a previous attempt left its
  evidence. Do not delete it. Only after the supervisor says so: `<venv python.exe> D:\p12_a6_work\a6.py archive-previous` moves
  D:\p12_a6_private and the previous state / report / logs into D:\p12_a6_work\archive\<stamp>\ (nothing is deleted); then re-run
  `validate`. `validate --resume` instead continues after the last completed stage (use only when the supervisor asks).
- `<venv python.exe> D:\p12_a6_work\a6.py status` prints the completed stages and whether A6 tasks are still installed.
- If the process was killed mid-way and `status` says TASKS_INSTALLED=YES, run `validate --resume` or paste the status and wait for
  instructions. Until the tasks are removed they would start the networkless CLI daily at the synthetic times; each such start can
  only end in ALREADY_SUCCEEDED / MISSED / RECOVERY_REQUIRED against D:\p12_a6_private (never the production roots).
